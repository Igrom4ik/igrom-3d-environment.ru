## 1) Единый helper URL ассетов

### Зачем
В проекте использовались разные форматы путей:

- только имя файла: `MilitaryHat_01_1.png` (ожидалось `public/images/uploads/...`);
- относительные пути: `images/uploads/...` или `uploads/...`;
- абсолютные публичные пути: `/images/uploads/...`;
- пути с префиксом `public/...`;
- внешние URL: `https://...`.

Это приводило к “битым” превью и несогласованности между сайтом/админкой/Keystatic.

### Что сделано
Добавлен единый слой нормализации URL:

- [assets.ts](file:///d:/igrom-3d-environment.ru/src/lib/assets.ts)
  - `getImageUrl(filePath)` — нормализация картинок (дефолт: `/images/uploads/...`).
  - `getMarmosetPackageUrl(filePath)` — нормализация marmoset-пакетов (дефолт: `/marmoset/...`).
  - `getPublicUrl(filePath)` — нормализация публичного URL (убирает `/public` и добавляет basePath).

## 2) Скролл в админке

### Симптом
“Во всех блоках админки не работает скролл”: контент обрезался, страница не прокручивалась.

### Причина
`overflow: hidden` использовался на контейнерах, которые были частью flex-раскладки. При этом scroll-контейнер (`overflow-y: auto`) оказывался в ситуации, где `min-height` по умолчанию мешал включению прокрутки.

### Что сделано
- В [portfolio.module.css](file:///d:/igrom-3d-environment.ru/src/app/admin/portfolio/portfolio.module.css) добавлены `min-height: 0` для корректной работы прокрутки внутри flex:
  - `.mainLayout { min-height: 0; }`
  - `.contentArea { min-height: 0; }`
- `/admin/upload` переведён на использование `.contentArea` (вместо `.mainLayout` с `overflow:hidden`):
  - [upload/ClientPage.tsx](file:///d:/igrom-3d-environment.ru/src/app/admin/upload/ClientPage.tsx)
- У `.adminBody` выставлены корректные overflow и высота viewport, чтобы вложенные `height: 100%` считались предсказуемо:
  - [admin-layout.module.css](file:///d:/igrom-3d-environment.ru/src/components/admin/admin-layout.module.css)

## 3) Скролл в Keystatic (`/keystatic/singleton/settings`)

### Симптом
На странице настроек Keystatic скроллинг отсутствовал.

### Причина
Кастомный редактор использует “внутренний” скролл, завязанный на `height: 100% / flex: 1`. Для стабильной работы этому нужен родитель с фиксированной высотой. Дополнительно правила в [custom.css](file:///d:/igrom-3d-environment.ru/src/resources/custom.css) для `data-preset="ios-liquid-glass"` не применялись к Keystatic, потому что у Keystatic-layout не было `data-preset` на `<html>`.

### Что сделано
- `.adminBody` сделан реальным scroll-контейнером: `height: 100vh`, `min-height: 0`, `overflow-y: auto`.
  - [admin-layout.module.css](file:///d:/igrom-3d-environment.ru/src/components/admin/admin-layout.module.css)
- В Keystatic-layout добавлен `data-preset="ios-liquid-glass"` на `<html>`, чтобы работали preset-правила из [custom.css](file:///d:/igrom-3d-environment.ru/src/resources/custom.css).
  - [keystatic/layout.tsx](file:///d:/igrom-3d-environment.ru/src/app/keystatic/layout.tsx)

## 4) `Failed to save settings` при загрузке нового аватара

### Симптом
При попытке загрузить новый аватар в Keystatic показывалось `Failed to save settings`.

### Причина
`PUT /api/admin/settings` иногда получал multipart-body, но без корректного `Content-Type: multipart/form-data`. В результате обработчик пытался распарсить тело как JSON (`request.json()`), падал, и возвращал 500.

### Что сделано
- В [settings/route.ts](file:///d:/igrom-3d-environment.ru/src/app/api/admin/settings/route.ts):
  - роут переведён на `force-dynamic` (запись на диск и загрузка файлов не должны быть “static”);
  - добавлен fallback: если JSON-парсинг не удался, читается raw body (через `request.clone()`) и парсится multipart по boundary из тела;
  - общий код сохранения/валидации аватара вынесен в единый путь обработки.
  - убрана зависимость от глобального `File` (на некоторых Node.js окружениях он может отсутствовать): файл проверяется как “file-like” объект с `arrayBuffer()`.

### Результат
Сохранение аватара возвращает корректные ответы:
- 200 при успешной операции,
- 400 с текстом причины при ошибке валидации,
- без 500 из-за неправильного парсинга тела.

## 5) Стабильный URL аватара и watcher

### Цель
Чтобы аватар не ломался после перезагрузки/деплоя и не появлялись 404 на `avatar-<timestamp>.webp`, принят единый URL:

- `/images/uploads/avatar.webp` (файл: `public/images/uploads/avatar.webp`)

### Что сделано
- Добавлен helper нормализации:
  - [avatar.ts](file:///d:/igrom-3d-environment.ru/src/lib/avatar.ts)
  - `normalizeAvatarPath(...)` возвращает `/images/uploads/avatar.webp` по умолчанию.
- API `/api/admin/settings` больше не пишет timestamp-имена:
  - при загрузке аватара перезаписывается один файл `avatar.webp`,
  - в `settings.json` принудительно записывается `person.avatar = "/images/uploads/avatar.webp"`.
- В админке:
  - аватар рендерится через `normalizeAvatarPath` и при ошибке загрузки делает fallback на `/images/avatar.jpg`:
    - [SettingsEditor.tsx](file:///d:/igrom-3d-environment.ru/src/components/admin/SettingsEditor.tsx)
  - watcher подписывается на `/api/admin/fs/watch?publicPath=/images/uploads/avatar.webp`.
- Watcher `/api/admin/fs/watch` переведён на `force-dynamic` и нормализует ведущие `/`:
  - [watch/route.ts](file:///d:/igrom-3d-environment.ru/src/app/api/admin/fs/watch/route.ts)
