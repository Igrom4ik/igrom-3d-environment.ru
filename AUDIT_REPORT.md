# Аудит Проекта Igrom Portfolio

## Дата аудита: 30 января 2026

## Обзор проекта

Проект представляет собой портфолио-сайт на Next.js с системой управления контентом Keystatic, интеграцией Supabase и Telegram. Использует TypeScript, SCSS-модули и библиотеку Once UI.

---

## 🔴 Критические проблемы

### 1. **Дублирование систем чтения данных**

**Проблема:** Существуют две параллельные системы для чтения контента:
- **Keystatic Reader** в `src/utils/reader.ts` - для работы с CMS
- **Файловая система** в `src/utils/utils.ts` - прямое чтение MDX файлов

**Последствия:**
- Удвоенная логика обработки контента
- Расходящиеся форматы данных
- Сложности в поддержке и отладке

**Пример дублирования:**
```typescript
// В reader.ts - Keystatic подход
const album = await reader.collections.albums.read(slug);

// В utils.ts - файловая система
const { data, content } = matter(fileContent);
```

### 2. **Непоследовательная структура хранения**

**Проблема:** Проекты хранятся в разных форматах:
- `src/content/albums/project-name/index.mdoc`
- `src/content/albums/project-name.mdoc`
- `src/content/albums/project-name/index.mdx`

**Последствия:**
- Сложная логика поиска файлов
- Потенциальные ошибки при сохранении
- Непредсказуемое поведение API

### 3. **Отсутствие валидации данных**

**Проблема:** Нет централизованной валидации входных данных в API endpoints.

**Пример в `route.local.ts`:**
```typescript
// Нет проверки типов входных данных
const data = await req.json();
const { slug, ...projectData } = data;
```

## 🟡 Потенциальные проблемы производительности

### 1. **Избыточные операции файловой системы**

**Проблема:** Каждый запрос к API выполняет множество операций чтения:
- Проверка существования файлов
- Поиск в разных директориях
- Чтение и парсинг MDX файлов

**Решение:** Использовать кэширование или предзагрузку данных.

### 2. **Большие бандлы клиентского кода**

**Проблема:** В `layout.tsx` встроен большой скрипт инициализации темы:
```javascript
// 50+ строк JavaScript встроены в HTML
{`(function() { /* ... */ })();`}
```

**Решение:** Вынести в отдельный файл, использовать Code Splitting.

### 3. **Отсутствие оптимизации изображений**

**Проблема:** Изображения не оптимизируются автоматически:
```typescript
// Прямые пути к изображениям без оптимизации
images: data.images || [],
```

## 🟢 Архитектурные недочеты

### 1. **Смешение ответственности**

**Проблема:** Компоненты выполняют слишком много задач:
- `Header.tsx` содержит логику часов и определения локации
- `reader.ts` содержит fallback логику вместо чистой абстракции

### 2. **Жесткая зависимость от файловой структуры**

**Проблема:** Код привязан к конкретной структуре папок:
```typescript
const albumsDir = path.join(process.cwd(), 'src/content/albums');
```

**Решение:** Использовать конфигурационные файлы или environment variables.

### 3. **Отсутствие единого стиля обработки ошибок**

**Проблемы:**
- В некоторых местах используется `console.error`
- В других - кастомный `log()` из `logger.ts`
- Нет централизованной обработки исключений

## 🔍 Дублирование кода

### 1. **Повторяющаяся логика обработки изображений**

**Файлы:** `utils.ts`, `reader.ts`, несколько API endpoints

**Дублирование:**
```typescript
// Повторяется в 3+ местах
img.startsWith("/") ? `${basePath}${img}` : img
```

### 2. **Похожие API endpoints**

**Проблема:** `/api/portfolio/get`, `/api/portfolio/save`, `/api/posts/[slug]` имеют схожую структуру но дублируют:
- Валидацию параметров
- Обработку ошибок
- Логику чтения файлов

### 3. **Повторяющиеся типы и интерфейсы**

**Проблема:** Типы для контента определены в нескольких местах:
- `types/content.types.ts`
- Внутри компонентов
- В Keystatic конфигурации

---

## 🛡️ Проблемы безопасности

### 1. **Отсутствие sanitization**

**Проблема:** Контент из MDX файлов не проходит sanitization перед рендерингом.

### 2. **Прямая работа с файловой системой**

**Проблема:** API endpoints напрямую работают с файловой системой без дополнительной проверки путей.

### 3. **Отсутствие rate limiting**

**Проблема:** API endpoints не имеют ограничений по количеству запросов.
